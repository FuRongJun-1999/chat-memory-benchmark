# 提交聊天记忆系统测试成绩

欢迎项目作者或使用者提交自己的测试结果。可以直接把下面这段话交给 Codex，让它完成测试、整理材料并准备 Pull Request：

```text
请按 https://github.com/Ornn8/chat-memory-benchmark/blob/main/docs/submit-results.md 的要求，
测试这个记忆系统：[仓库地址或本地路径]。
请使用正式六人物测试集，保存真实回答、逐题判分和测试配置，统计成绩后准备投稿。
先告知我预计使用的模型与费用，未经我同意不要上传密钥或私人数据。
```

## 一、使用哪套题

- 使用仓库内的[六人物正式测试集](../datasets/natural-timegrid-20261101-v2/)，共 714 题，并记录题库版本或 `manifest.json` 的 SHA-256。单人物示例可用于调试，不作为正式六人物成绩。
- 尽量完成全部题目。遇到中断或未产生回答时，保留题号及原因；成绩写为“通过题数 / 实际判分题数”，同时写明未答题数。不要编造回答，也不要把未答题当作已经判错。
- 不更改历史、题目或标准答案。发现题目有歧义，可以附题号和依据反馈。

## 二、怎样考试

具体流程见[测试方法](methodology.md)和[接入说明](integration.md)。投稿时请遵守以下几点：

1. 六个人物使用相互隔离的记忆。按时间把已有的用户消息和助手回复交给被测系统处理；按系统实际机制执行应有的整理、归档或维护。
2. 每道题只使用该题截止点以前的历史和记忆；按题目时间推进测试进程内的逻辑时间。可以增量处理历史，无需为每道题保存快照。
3. 通过系统的原生问答或记忆检索流程作答，写明直接提供给模型的近期对话窗口。不要将完整历史、人物设定、标准答案或判分提示直接交给作答模型，也不要为个别题目手工补入正确证据。
4. 考试时系统自主调用记忆工具的行为可以保留并如实记录；需要隔离本题的考试影响，避免把题目、答案或相关写入带到后续题目。不要通过反复重试挑选正确回答；重试和中断如实记录。
5. 如果调整了归档阈值、记忆窗口、检索次数等默认设置，写出调整前后及原因。系统使用独立作答模型或额外检索时，也请注明。

## 三、投稿需要提供什么

请在 Pull Request 中提供以下材料，或者在 Issue 中给出可公开访问的材料链接：

| 材料 | 需要包含的内容 |
| --- | --- |
| 项目与版本 | 项目名称、作者、仓库地址、具体版本和 commit；若使用宿主、插件或适配器，也注明版本及地址。 |
| 测试配置 | 题库版本；六个人物的处理方式；记忆写入、检索、整理与定时机制；直接对话窗口；模型及嵌入、重排模型；实际改动的默认参数。 |
| 逐题真实回答 | UTF-8 JSONL，每行至少包含 `id` 和最终给用户的 `answer`；题号与正式题库一致，不重复、不替换模型回答。未答题单独列题号与原因。 |
| 判分与统计 | 判分者或判分模型及版本、判分方式、每题判定与理由；总通过数 / 已判题数、各考点和各时间间隔的通过数 / 题数。 |
| 运行情况 | 是否完整跑完、失败与重试、运行中的限制或报错；有改动时写明修改内容。 |
| 消耗与耗时 | 如有记录，提供记忆处理、检索、作答和判分的用量及时间，并注明是实际账单、订阅额度还是按单价折算；未记录的部分写明即可。 |

作答文件示例：

```json
{"id":"P01-CASE-001/d03","answer":"系统实际给用户的回答"}
```

有条件的话，请一并提供适配代码和可复现的运行命令。大型运行日志可保留在外部，只提供必要的公开链接和说明；不要提交 API key、密码、私人聊天或真实用户身份资料。

## 四、怎样判分

推荐使用仓库提供的[判分工具和说明](../grading/README.md)：先准备题目、证据和回答，交给 Codex 对照判断，再运行工具生成逐题结果与汇总。

```sh
python grading/grade.py prepare --answers answers.jsonl --out packets.jsonl
# 依据 grading/judge-prompt.md 判定各题，生成 reviews.jsonl
python grading/grade.py score --packets packets.jsonl --reviews reviews.jsonl --out judgments.jsonl --summary summary.json
```

语义判断需要判分者结合证据完成，脚本负责校验题号和哈希并汇总规则。请提交 `answers.jsonl`、`reviews.jsonl`、`judgments.jsonl`、`summary.json`；其中判分记录与回答必须通过工具的哈希校验。也欢迎提交其他判分方式的结果，但请保留逐题依据并注明判分者、模型和规则；不同判分方式会在成绩记录中写清。

## 五、提交与展示

1. Fork 本仓库，在 `results/submissions/<项目名>-<版本或日期>/` 中放入材料和一份简短的 `README.md`，说明上表中的配置、成绩和运行情况。
2. 发起 Pull Request，标题注明项目及版本；正文写明总成绩、完成题数、主要配置和材料位置。无法发 PR 时，也可以发 Issue 并提供材料链接。
3. 维护者会核对题号、回答、统计与测试配置；需要澄清的地方会在 PR 或 Issue 中沟通。作者自测会标明来源，不会写成维护者独立复现。

与其他系统比较时，使用相同题号的共同已答集合，并保留各自完整的已答题数。一个题可属于多个考点，不能把各考点题数相加作为总题数。
