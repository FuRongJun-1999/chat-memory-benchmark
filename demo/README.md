# 记忆系统评测：一个人物的公开示例

这是独立新写的公开演示材料，人物、生活事件、对话、问题和答案全部虚构。只沿用现有评测的结构和考点，不使用正式考卷中的人物事实、问题或答案，不包含真实用户聊天、账户、逐用户统计或私有来源映射。

**一个虚构人物，182 天、360 轮对话，27 个独立事实组，每组在当天、3 天、15 天、45 天提问，共 108 个实例。** 一个事实重复问四次不是四个独立事实。每个考点、每个间隔只提供一道示例，不达到正式排名使用的每格至少十题要求，也不据此排名。

## 怎么看

- 双击 `示例题.html`：按考点和时间筛选，查看题目、原始依据、通过条件和人工参考答案；无需联网。
- `示例题.md`：完整可读题目说明。
- `完整对话.md`：按时间阅读全部 360 轮聊天。
- `character.json`：虚构人物设定，仅供理解创作背景，不能当成额外记忆喂给系统。

## 怎么接到系统里

Python 3.10 或更新版本即可，无第三方依赖：

```sh
python read_exam.py --verify-all
python read_exam.py --id PUB01-C001/d45 --output question.json
```

导出的 `question.json` 只有题目、时间、截止轮、历史 SHA 和可读取的对话前缀，没有参考答案或评分依据。

1. 把该题允许的历史前缀按时间顺序交给被测系统自己的记忆入口。时间表示该轮用户消息与助手回复均已完成；1 轮就是一问一答。
2. 若系统有夜间整理或 Dream，按逻辑时间调用其原生维护。执行方法和开关需要另行记录，不能把“时间改了”当作“维护执行了”。
3. 在该系统正常问答入口发送题目。若需要统一作答模型，必须明确记录这一配置。
4. 每道题从相应历史快照独立作答；不要把考题和考试回答写回后续历史。不可提前导入 `cutoff_turn` 后的消息。
5. 评分时再读取 `review-only/answer-key.jsonl`。`review-only/`、网页、Markdown 和人物卡均不能作为考试输入。

间隔从**实际评分事实最后一次提及**计算，用户和助手的复述都计入。当天实例在最后提及后一秒提问，另外三档分别为准确的 3、15、45 天。多事实题逐项记录时间锚，题组间隔按最近的评分事实计算。近期六轮是否包含评分事实另行标记，不能把短期上下文答对一概称为长期记忆成功。

## 怎样判

只看题目要求的事实、时间、主体和边界；不评文风、语气或措辞相似度。必须满足所有 `required`，并且不犯 `forbidden` 列出的错误；`unknown` 中的内容没有证据，不能编造。参考答案是一种合格写法，不是唯一字面答案。

问题在四个时间档保留同一判据；过去的计划、假设与当时的限制按历史语境提问，不假定它们到 45 天后仍有效。少数边界题依靠一般常识也可能答对，`retrieval_required: false` 会明确标注。

## 文件与验证范围

- `histories/PUB01.jsonl`：可导入的对话历史。
- `exam-inputs.jsonl`：不含答案的 108 个题目实例。
- `review-only/cases-PUB01.jsonl`：27 个事实组、逐字证据和判分解释。
- `review-only/answer-key.jsonl`：每个实例的答案、时间锚和标准；仅供判分。
- `statistics.json`：规模、时间档和覆盖数量。
- `manifest.json`：文件 SHA，用于确认使用的是同一版本；SHA 不代表题目质量已得到外部认证。
